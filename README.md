/**
 * STRATEGY & DISCIPLINE
 * ------------------------------------
 * 1. Stay calm, relaxed, but "contest-active." 
 * 2. Avoid a "cannot solve" mindset.
 * 3. Record time: Reading -> Idea -> Verification -> Coding -> Debugging.
 * 4. Read slowly and systematically. 
 * 5. Ensure no statement conflicts with your understanding.
 * 6. Note down essential rules/conditions on paper.
 * 7. Analyze bounds (N = 0, 1, max). 
 * 8. Look for "Special Constraints" that simplify the logic.
 * 9. Never code without verifying the idea.
 * 10. Tracing samples on paper saves debugging time.
 * 11. Don't assume input order (e.g., A < B) unless explicitly stated.
 * 12. Double-check precision, special cases, and specific formatting.
 * ------------------------------------
 * "Work Smart, Not Hard. Vision-driven training beats random practice."
 */

 /**
 * IMPLEMENTATION
 * -----------------------------------
 * 1. Avoid the "PC Trap." Brain power is limited when typing syntax; 
 * 2. use paper to free your mind for core logic and hidden edge cases.
 * 3. Easy: Direct coding is okay.
 * 4. Medium: Sketch the idea and verify Time/Memory Complexity on paper first.
 * 5. Hard: Full logic sketching and Pseudo-code on paper are mandatory.
 * 6. If the implementation is complex (heavy simulation/many conditions), 
 * 7. write the core logic on paper. It makes the final typing a 5-minute task.
 * 8. If you hit a bug, don't just "try i+1." Step away from the PC, 
 * 9. return to your paper, and find the real logical fix.
 * 10. 1 PC + 3 Members = Resource War. 
 * 11. A team that thinks on paper gets 15 hours of productivity, not 5. 
 * 12. Only sit at the PC when your code is ready to be "dumped."
 * -----------------------------------
 * "A PC is for implementation; Paper is for thinking. Don't mix the two."
 */
